Recomendación CHUNK_SIZE

Fase 1: Mantener 900 para comparar manzanas con manzanas.

Recomendación TOP_K

Con bge-m3 y CHUNK_SIZE=900: Mantener TOP_K=6. La mejor calidad vectorial hace que los 6 resultados sean más relevantes → no necesitas más.
Con CHUNK_SIZE=1400: Podría bajarse a TOP_K=5 porque cada chunk tiene más contexto. Esto compensa el aumento de chars/chunk y mantiene un presupuesto de tokens similar al LLM.
Solo subir a 8 para queries de comparación/resumen donde necesitas diversidad de fuentes. Ya hay lógica de diversity_target en el scoring que gestiona esto.

Nota importante: RAG_BACKEND=azure_search en producción

En Azure el backend usa Azure AI Search, no ChromaDB. El campo vectorial content_vector necesitará redimensionarse de 384 a 1024 dims al cambiar a bge-m3. Esto requiere recrear el índice de Azure AI Search (cambiar dimensiones en el schema y reindexar desde Blob Storage).

Cambio necesario en el índice Azure AI Search

El campo content_vector está definido como dimensions: 384 en el schema del índice. Al migrar a bge-m3 hay que cambiarlo a dimensions: 1024. Esto requiere borrar y recrear el índice (Azure AI Search no permite cambiar dimensiones en caliente). El script LanzarChatbotNube.bat ya tiene la lógica de creación del índice — solo hay que actualizar la dimensión en el JSON de definición.

2.4 Cambios en Dockerfile y despliegue

# Dockerfile — Cambios para bge-m3

ARG RERANK_MODEL=paraphrase-multilingual-MiniLM-L12-v2
ARG EMBEDDING_MODEL=BAAI/bge-m3
ARG RERANK_MODEL=${EMBEDDING_MODEL}

ENV ...
    EMBEDDING_MODEL=${EMBEDDING_MODEL} \
    RERANK_MODEL=${RERANK_MODEL} \
    ...

# La línea de pre-descarga del modelo se mantiene igual
# (SentenceTransformer descarga bge-m3 en build time)
RUN python -c "from sentence_transformers import SentenceTransformer; \
    SentenceTransformer(os.environ['EMBEDDING_MODEL'])"

# LanzarChatbotNube.bat — Cambios en vector field dims

# En la definición del índice Azure AI Search (línea ~274):
fields = @(
    ...
    @{
        name = "content_vector"
        type = "Collection(Edm.Single)"
        searchable = $true
        dimensions = 384
        dimensions = 1024
        vectorSearchProfile = "default"
    }
    ...
)

Conclusión de escalado

Con bge-m3 (FP16) + Azure AI Search Basic, el coste se mantiene en ~$122/mes hasta ~40 PDFs (PRL + RRHH + Calidad + normativa eléctrica). El plan Basic de AI Search soporta hasta 2 GB de índice, que con 1024 dims da para ~120K chunks. Solo si se supera ese umbral hay que subir a S1 ($250/mes).

El ahorro indirecto también importa: mejor retrieval → menos fallbacks al modelo caro gpt-4.1-mini → menos coste OpenAI.
